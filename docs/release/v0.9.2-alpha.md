# v0.9.2-alpha — Linux Distribution v2

[Public alpha prerelease](https://github.com/pixelrhino-ai/vrhino/releases/tag/v0.9.2-alpha).
This publication promotes the same two archive bytes qualified as
`v0.9.2-rc1`. It is an alpha release, not stable/GA. The core archive retains
its original v0.9.1 build version; `vrhino --version` reports that embedded
version. The v0.9.2 tag identifies the distribution publication.

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/pixelrhino-ai/vrhino/v0.9.2-alpha/install.sh | sh
```

The versioned `install.sh` pins the final catalog SHA256
`d3890bd1b0d2d95f7be3500eb861abd84d2be4db4b77d70dfc600966d3a0fa80`
and the qualified installer SHA256
`b1780b4e1bc652b5a954a713497abf65b7f95665e814d48ca78e8e8c95b436e7`.
It retrieves both over HTTPS, verifies the installer, and passes the independent
catalog pin to it. The catalog's own `.sha256` companion is an integrity aid,
not the trust root. The catalog pins exact archive URLs, SHA256 values,
runtime ID, platform, and runtime API. No floating CUDA match or system CUDA
fallback is accepted.

The first installation downloads 1,411,496,250 archive bytes: core plus NVIDIA
runtime. If a future core declares the same exact runtime identity, the
installer verifies and reuses the existing private dependency, so only the
new core archive must be downloaded. The current core archive is 36,064,164
bytes. Model weights remain separate under `vrhino pull`.

Linux x86_64, glibc 2.35 or newer, a compatible NVIDIA GPU/Driver, and enough
VRAM and disk space are required. CUDA Toolkit, system cuDNN, system FFmpeg,
Python inference environment, and sudo are not required.

## Upgrade, offline use, and rollback

The installer recognizes installer-managed v0.9.1 monolithic launchers, keeps
their package tree intact, installs the exact v2 NVIDIA runtime artifact in
its own dependency store, saves the old launchers, and atomically switches the
active pointer. Users do not uninstall v0.9.1 first. The old embedded vendor
libraries are not inferred to equal the v2 artifact from version strings.

Offline users place the two archives, the exact `install_distribution_v2.sh`,
and the final catalog copied to `catalog.txt` in one directory, then run a
local copy of this versioned `install.sh --bundle-dir DIR`. The same outer,
internal, dependency, and catalog checks apply. To return a migrated install
to v0.9.1, run the published `rollback_distribution_v2_legacy.sh`; it switches
the active pointer to the preserved monolithic installation. The historical
[v0.9.1 release](v0.9.1-alpha.md) and its installer remain available.

archives carry applicable Product evidence: Wan2.1 PASS, LTX PASS, Mochi PASS,
and Wan2.2 EXPECTED_HOLD_REPRODUCED. Wan2.2's normal Product path can produce
video; its historical generic numerical HOLD remains unchanged. No Runtime,
Backend, CUDA, PrecisionPolicy, or numerical gate semantics changed. A short
external smoke using the final v0.9.2-alpha URL is pending after publication.
