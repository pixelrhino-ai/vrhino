# VRhino v0.9.4-alpha — Wan2.1 runtime and peak memory improvements

## Install and downloads

```sh
curl -fsSL https://raw.githubusercontent.com/pixelrhino-ai/vrhino/v0.9.4-alpha/install.sh | sh
```

Linux x86_64, glibc 2.35+, a compatible NVIDIA GPU/driver and enough memory
and storage are required. The SHA-pinned installer downloads the core and its
exact private NVIDIA runtime. Existing verified R1 installations reuse that
runtime. No system CUDA Toolkit, cuDNN, FFmpeg or Python inference environment
is required; model weights remain separate.

Exactly two download assets:

- **Core:** `vrhino-core-linux-x86_64-v0.9.4-alpha.tar.gz` (36,211,068 bytes).
- **NVIDIA Runtime:** `vrhino-nvidia-runtime-linux-x86_64-cuda12.8-cudnn9.8-r1.tar.gz` (1,375,432,086 bytes).

The core contains new executables built as **v0.9.4-alpha** from
`77bf96f5e6059f3643da378f274bbd58e7c5e835`, based on merged performance source
`55922514062f52fb2a9dc1f1cc03b725e9af443e`.
This is not a metadata-only repackage of the old binary. NVIDIA R1, non-NVIDIA
libraries and media payload bytes are unchanged. Older releases remain immutable.

## Main result: controlled VRhino before/after comparison

**In the measured Wan2.1 T2V 1.3B / RTX 4090 D scene, complete generation time
fell 7.72% and sampled peak device memory fell 30.93%; checkpoints and video
outputs remained identical on the tested inputs.**

| Metric | Before five optimizations | After five optimizations |
|---|---:|---:|
| Full command wall time, median (range), s | 306.356 (305.492–306.402) | 282.720 (282.013–283.539) |
| Device-total peak, median (range), MiB, 1s sampling | 13,941 (13,845–13,941) | 9,629 (9,629–9,629) |
| Backend high water, GiB | 13.25 (13.16–13.25) | 9.04 |
| Main-process HWM, median, GiB, 0.5s observation | 11.355 | 9.413 |

Three complete fresh-process runs per side, interleaved, without a heavy
profiler or checkpoint export during timing. Wall time includes loading,
required verification, initialization, generation, media and process exit;
compilation/acquisition are excluded. Host HWM excludes media child processes.
Device samples are not strict instantaneous peak bounds; Backend statistics
are separate and are not added to device totals. File pages were already warm;
no system cache clearing, clock changes or GPU-resident cross-process service.

Same source base `8917863834cd64a59a3524e47b4425fabb8ffe12`, with/without
only the five accepted changes. Optimized `5e5e0ea` has the same tree as merged
`5592251`. This measured source A/B is **not** a direct benchmark of an older
published archive against this newly built archive, nor a sum of round percentages.
[All six timing rows](v0.9.4-alpha-wan21.csv).

Task: `vrhino/wan2.1-t2v-1.3b:1.0.1`, prompt `A red panda running through fresh snow`,
seed5701, original negative conditioning, 832×480, 81 frames, 16 FPS,
50 steps, guidance5, flow shift5, second-order UniPC and unchanged BF16 policy.
Both source builds used Release/GCC11.4/nvcc12.8.93/SM89/cuDNN9.8/cuBLASLt12.8.4;
GPU RTX4090D/driver580.105.08, CPU Xeon Platinum8352V.
Resource budgets were unchanged: device21GiB, activation2GiB, host64GiB,
staging2GiB and safety1GiB.

The five general changes are request-owned RoPE position reuse, CUDA binary
broadcast indexing, runtime-dispatched AVX2 BLAKE2b with scalar fallback and
full-file verification, idle device resource reclamation after complete
sampling, and host-resident gather rows selected before upload. No model
identity special cases, task reduction, new precision or approximate algorithm.

## Correctness and release validation

Two source A/B inputs (main seed5701; longer text/seed1234) each had all 413
available checkpoints, final latent/video tensors and all 81 decoded frames
byte-identical. Applicable generic/component/CUDA/lifecycle tests passed.
The new release build additionally passed 17 affected/image/version tests,
22 Distribution v2 tests, private dependency loading and isolated installation.
The packaged Wan2.1 normal Product smoke also passed using a sanitized PATH
and private dependencies: all 81 frames and the MP4 were byte-identical to the
validated 5592251 source output. Required Public CI gates the release PR.
This package smoke is an integration check, not another performance A/B.

The archive contains native images for SM80/86/89/90/120 plus compute80 PTX.
This binary is exercised on RTX4090D; image inclusion does not qualify every
GPU/model combination. Other real models, GPU families, CPU architectures,
Windows and macOS were not requalified for this release. Existing Windows
v0.8 assets remain unchanged. No smaller-memory GPU support is claimed.
The direct-Backend empty-batch indexed_gather SIGFPE remains a baseline issue
with an unspecified contract; it is not fixed here or treated as PASS.
Historical numerical HOLDs and existing gates/PrecisionPolicy are unchanged.

## Additional official comparison — different execution strategies

Official source fixed at
[`9737cba9c1c3c4d04b33fcad41c111989865d315`](https://github.com/Wan-Video/Wan2.1/tree/9737cba9c1c3c4d04b33fcad41c111989865d315),
VRhino at `5592251`, same machine and task/checkpoint provenance
`Wan-AI/Wan2.1-T2V-1.3B@37ec512624d61f7aa208f7ea8140a131f93afc9a`.
Solver/shift/50 integer timesteps match; sigma construction differs at most
5.96e-8. Prompt extension is disabled. Three normal fresh processes per side.

| Metric | Official documented low-memory route | VRhino normal Product |
|---|---|---|
| Strategy/precision | T5 CPU BF16; DiT F32 parameters/BF16 autocast, F32 sampling state; GPU VAE F32; offload after sampling | GPU T5/DiT/VAE; existing BF16 policy, F32 statistics/residuals; idle resources reclaimed after sampling |
| Full wall median (range), s | 425.318 (421.150–426.275) | 283.307 (280.526–283.730) |
| Device peak, MiB, 1s sampling | 13,129 each run | 9,629 each run |
| Main-process HWM median (range), GiB | 23.861 (23.782–23.862) | 9.413 (9.412–9.413) |

[All six comparison rows](v0.9.4-alpha-official-comparison.csv).
Official environment: Python3.12.3, Torch2.8.0+cu128, FlashAttention2.8.3.post1,
cuDNN9.10.2.21, Transformers4.51.3, Diffusers0.39.0; VRhino uses cuDNN9.8 SDPA.
CPU OMP/MKL threads16. Official `offload_model=True, t5_cpu=True` unloads DiT
only after the entire sampling loop in this fixed source. Initialization
median86.596s and CPU conditioning41.734s explain much of the total difference;
remaining kernel-level attribution is unknown. Official allocated/reserved and
VRhino Backend metrics are not interchangeable. Main HWM excludes FFmpeg.
Official final finite-check overhead13–21ms is included in wall time, with no
large HOST export; all observed memory peaks preceded it.

Media defaults also differ: official FFmpeg7.0.2/libx264 CRF10, VRhino
FFmpeg4.4.2/libx264 CRF23. All six videos decode at the requested geometry/FPS,
with no blank frames or nonfinite raw output; sampled frames contain the
requested subject and snow. Composition/motion differ. Same seed does not
imply identical initial noise or video across frameworks.
**No complete subjective video/temporal quality evaluation was performed;
there is no equal-quality superiority claim.** The total difference reflects
these strategies/precision/defaults, not an unconditional Native-versus-PyTorch claim.
